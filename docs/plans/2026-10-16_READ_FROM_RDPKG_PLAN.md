### Що з'ясовано в коді (17.10)

- Встановлений том = `.rdpkg`, розпакований 1:1 (`RdpkgImporter.extract`), записи в `.rdpkg` — DEFLATED рівня 0 (`RdpkgZipWriter`), тобто майже без стиснення.
- Усе читання тому йде через **дві точки**: `LocalDatasetDocumentsProvider` (`queryChildDocuments`, `openDocument`) і прямий шлях `SafDatasetResolver.directNode` (v0.5.138, `VolumeFileIndex`). Інших місць, що читають файли тому з диска напряму, немає.
- Довільний доступ (seek) потрібен лише PDF: `AndroidPdfLayer.openPdf` → `PdfRenderer(pfd)`. Сторінки, JSON, Fast Pack читаються потоком.

### Як буде

- Архів тому лежить **поруч із теперішніми томами**, у папці застосунку, в окремій теці: телефон `noBackupFilesDir/rdpkg-archive/<id>.rdpkg`, карта `Android/data/com.saney.renaultdocs/files/rdpkg-archive/<id>.rdpkg` (дозволів не треба, `.nomedia` — першим, в бекапи не йде). _(Уточнено при коді v0.5.141: окрема тека, щоб файл не плутався з папками томів.)_
- `ZipFile` відкривається раз на том (зміст ~8 тис. записів — у пам'ять), далі файл тому = запис в архіві.
- Сторінки, JSON — потоком з архіву. **PDF** — витягується в кеш телефона (`cacheDir`, ліміт ~300 МБ, найстаріші прибираються лише з цієї папки) і відкривається звідти; намальовані сторінки й далі в `PdfPageDiskCache`.
- Якщо поруч і архів, і розпакована папка — читаємо з архіву лише після перевірки «кожен файл архіву = файл папки»; папка лишається, доки власник не скаже «так».

### Етапи (кожен — окрема версія; видалення — лише в етапі 3 і лише з «так»)

1. **Читання з архіву + «Зробити архів тому».** Друге джерело в провайдері й `directNode`; PDF через кеш. У меню тому — «Зробити архів тому»: `RdpkgExporter` пакує том з папки в `<id>.rdpkg` поруч, перевіряє кожен файл (розмір + CRC) проти папки, потім том читається з архіву. Нічого не видаляє. Перевірка на телефоні — на одному томі в пам'яті A26 (швидко), порівняти з тим самим томом до архіву.
2. **Імпорт = копія одного файлу.** Імпорт `.rdproject` / `.rdpkg` / «Готові проєкти» кладе `.rdpkg` як є (sha256 з каталогу/файлу), без розпакування. Розпаковувати — лише якщо файл старого формату не читається з архіву (запасний шлях).
3. **18 розпакованих томів Megane II на карті M30s.** Архів для кожного (як в етапі 1, або взяти `.rdpkg` з `.rdproject`, якщо він є на M30s — швидше), перевірка, перемикання; список розпакованих папок і розмір → **«так» власника** → прибрати (разом з `.import-…`, TODO №10; замінює TODO №6).
4. **(За бажанням) видима папка `Renault Docs/packages/`** — питання 1 і 4 з `2026-10-16_ARCHIVE_FOLDER_PLAN.md`; питання 2–3 (робочі копії) відпали.

## Що є зараз (з коду)

- Встановлений том = **розпакована папка**: ~6–8 тис. файлів, ~400 МБ (NT8340A: 8012 файлів). На карті — `Android/data/com.saney.renaultdocs/files/rdpkg/<id>/`, у телефоні — `noBackupFilesDir/rdpkg/<id>/`.
- `.rdpkg` = ZIP одного тому (70–130 МБ), записи DEFLATED рівня 0 — тобто майже без стиснення, читати шматок з середини швидко.
- **Уже є «Fast Pack»**: веб-частина тому (сторінки розділів, ~6 тис. файлів) лежить усередині тому одним ZIP (`renault-dataset.json` → `fast_pack`, `zip-web-v1`). Переглядач (`SafDatasetWebViewClient`) копіює його в кеш телефона за sha256 і читає звідти через `ZipFile` (`FastContentArchive`). Тобто читання з одного архіву вже працює в нашому коді.
- Решта (PDF, індекси розділів, каталоги) читається з розпакованої папки через `SafDatasetResolver` / `LocalDatasetDocumentsProvider` — на карті кожен такий файл іде через службу медіа Android 11 (FuseDaemon). Це й гальмує (TODO №12, №16).

## Мета

Том на карті — **один файл `.rdpkg`**. Застосунок читає з нього напряму, нічого не розпаковуючи. Тисячі файлів на карті зникають; імпорт на карту = копія одного файлу на том (хвилини, а не години).
