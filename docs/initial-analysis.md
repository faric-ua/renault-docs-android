## Головний висновок

У цій збірці не знайдено Windows-адрес типу `C:\\...`, `file://...` або локальних шляхів із зворотним слешем.

Документація вже використовує web-style відносні шляхи, наприклад:

`../../../COMMUN/PDF/SCH/0207_A3.PDF`

Отже головна проблема Windows → Android/Linux тут не формат шляху, а **чутливість файлової системи до регістру**.

## Динамічний JavaScript

Додаткова перевірка показала, що попередня оцінка про сім проблемних `VISU.JS` була завищена через закоментовані історичні рядки.

Активний lowercase-код реально є лише у **2** версіях:

- `Laguna X74 NT8240A 2003_11_17/COMMUN/JS/VISU.JS`
- `Laguna X74 NT8254A 2004_06_21/COMMUN/JS/VISU.JS`

У них динамічно формуються `_print` та `_printNB`, тоді як реальні PDF використовують `_PRINT` та `_PRINTNB`.

Ще у п'яти новіших `VISU.JS` lowercase-варіанти залишилися лише в коментарях, а активний код уже використовує uppercase.

Конвертер був прогнаний на повній копії архіву.

Результат:

- **16 877** статичних замін входжень (16 866 унікальних source/reference пар; 11 посилань повторюються в тому самому файлі);
- **4** активні JavaScript-заміни `_print/_printNB`;
- після повторної перевірки: **0 case-sensitive локальних посилань**;
- після повторної перевірки: **0 активних lowercase `_print/_printNB`**.

Оригінальний архів при цьому не змінюється — конвертер створює окрему копію.

## Що зберігаємо в GitHub

Після перевірки вирішено **не копіювати 1 500+ файлів Renault у репозиторій**.

У GitHub зберігаємо тільки:

- аналізатор;
- конвертер;
- manifests і статистику;
- автоматичні тести;
- Web/Android-оболонки;
- власну технічну документацію.

Оригінальна документація Renault лишається зовнішнім вхідним набором. Це робить репозиторій компактним і дозволяє застосовувати той самий конвертер до інших збірок Renault.
