# Renault Docs — правила роботи для Claude

Цей файл Claude читає на початку кожної сесії. Тут лише правила і карта.
Поточний стан проєкту — у `STATUS.md`. Історія — у журналі `docs/assistant-kit/PROJECT_LEDGER.md`.

## Хто з ким працює

- Власник проєкту — **faric**. Звертатися «faric», українською.
- faric не програміст і працює **тільки з телефона**: Android + Termux + Renault Termux menu (`menu.sh`).
  Часто надиктовує голосом, з суржиком. Розпізнавання може перекрутити назви: «Fabric UA» = `faric-ua`, «Reynolds Docs» = `renault-docs-android`.
- Claude працює у **своїй хмарній копії** репозиторію, не на телефоні. Спільна точка — GitHub.

## Робочий цикл

1. faric ставить задачу.
2. Claude читає `STATUS.md`, потрібний код і контракти. Якщо задача неясна — **одне** питання.
3. Claude пише код і тести → гілка → PR → чекає зеленого CI (`Tests`, `Android PR Check`) → **мержить сам**.
4. Якщо є що перевірити на телефоні — Claude **сам публікує реліз** (див. нижче) і дає faric короткий шлях у меню.
5. faric присилає скріншот або «пас / не пас». Claude фіксує результат у `STATUS.md` і журналі, дає наступний крок.

## Як говорити з faric

- Спочатку суть, без технічного шуму. Пояснювати простими словами.
- Дії на телефоні — **тільки шляхом меню**, напр. `5 → 19 → 8 → 13`. Shell-команди — лише для аварійної діагностики, якщо в меню немає аналога.
- Пункт **7** не є звичайним шляхом оновлення.
- Кожна робоча відповідь закінчується блоком **«Від тебе зараз:»** — один-два конкретні кроки. Якщо нічого не треба — так і написати.
- Під час QA: один крок за раз, не перестрибувати.
- Перевірки, які можна зробити кодом (тести, аудити архівів/пакетів/посилань/PDF), Claude робить **сам**. faric просимо лише те, що видно тільки на телефоні.

## Головні правила

- **Джерело правди — телефон.** Зелений CI або підписаний APK ≠ phone PASS. Не писати PASS без доказу з телефона.
- **Безпека даних:** ніколи не просити видаляти застосунок, чистити дані, перевстановлювати, повторно імпортувати томи «для тесту». Не чіпати оригінальні архіви, Drive-файли, встановлені томи. Нічого не видаляти мовчки.
- **NT-коди різні:** NT8340A ≠ NT8342A. Не зливати томи за схожою назвою.
- **Порядок релізів:** спершу Core Stable (#147), лише потім вхід/друзі/оплата (#133 BLOCKED).
- **Файли томів — лише для застосунку** (власник 2026-10-15): не індексуються (Галерея / служба медіа), не синхронізуються, не йдуть у резервні копії. Будь-яка папка з томами поза приватною пам'яттю (карта пам'яті тощо) — спершу `.nomedia`, потім файли.
- Не комітити захищені документи Renault, приватні Drive ID/URL, секрети, production keystore.

## Документація = майбутній урок

Історію проблем, невдалих спроб і рішень **зберігаємо повністю** — з неї планується урок з програмування.
- Нічого з історії не видаляти і не переносити без запиту faric.
- Новий запис у журнал — **одне місце**: верх `docs/assistant-kit/PROJECT_LEDGER.md` (новіші зверху). Коротко: що хотіли, що зробили, що не вийшло і чому, чим довели.
- `STATUS.md` — короткий, завжди актуальний. Переписувати, а не дописувати.
- `TODO.md` — дрібні правки з перевірок. Окремими версіями їх не випускати — робити одним заходом (власник 2026-10-14).
- Старі файли `CURRENT_PLAN.md`, `CURRENT_HANDOFF.md`, `ACTIVE_PLAN.md`, `ASSISTANT_CONTEXT_INDEX.md`, `SESSION_CHECKPOINT_*` — історичний архів, не дублювати в них кожен крок.

## Технічне

- Тести: `python3 -m unittest discover -s tests` (pytest недоступний у середовищі Claude).
- У середовищі Claude **немає Android SDK** і доступу до Google Maven — Gradle-збірка тут не працює. APK збирає GitHub Actions:
  - `android-pr-check.yml` — на PR (ephemeral ключ, **не ставити на телефон**);
  - `android-debug.yml` — на `main`, стабільний підпис;
  - `publish-verified-apk.yml` — публікує GitHub Release з `docs/release-promotions/vX.Y.Z.json`.
- Реліз: після успішного `Android Debug APK` на `main` — окремий PR з `docs/release-promotions/vX.Y.Z.json` (див. `docs/assistant-kit/GITHUB_RELEASES_CONTRACT.md`), merge → publisher workflow.
- Версія: `android/app/build.gradle.kts` (`versionName`, `versionCode`).
- GitHub: REST через `gh api` працює, GraphQL — ні.
- Телефон отримує зміни: меню `5` (оновити) / `16` (тестовий PR), APK: `5 → 19 → 8 → 13`, встановлювати **поверх** існуючої версії.
